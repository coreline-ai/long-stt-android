작성 일시: `2026-08-08 10:46:57 KST`

이 문서는 Phase 6의 단일 STT 화면 분해와 route 책임 정리 범위를 고정하고, 기존 장시간 전사·녹음 그룹·보관함 동작을 유지하기 위한 작업 문서다.

## 개발 목적

1,083행 `SttBenchmarkScreen.kt`의 전사·결과·설정 UI를 실제 앱의 4개 route 목적에 맞게 분리한다. 전사 route에는 모델 선택·오디오 선택·실행·진행만 남기고, 결과는 보관함, 모델 설치·기기 정보·Codex·개발 진단은 설정에서 관리한다. dialog 선택 상태는 route별 `SavedStateHandle` ViewModel이 소유해 configuration change와 route 재진입 뒤에도 일관성을 유지한다.

## 개발 범위

- `ui/transcription` 패키지와 `TranscriptionScreen`/route state ViewModel 신설
- 설치 모델 선택과 모델 설치·삭제 책임 분리
- 기존 오디오 import/선택/숨기기/파일 삭제 흐름의 전사·보관함 배치 정리
- `LibraryScreen` dialog state를 `LibraryRouteViewModel`로 이동
- `SettingsScreen` dialog state, 모델 관리, 성능 기록, device diagnostics 통합
- 설정의 카드 중심 표현을 section label·hairline divider 중심으로 정리
- Debug 자동 전사 진입을 신규 전사 route로 전환
- 구 `SttBenchmarkScreen`은 얇은 호환 wrapper로 축소
- route 상태·핵심 화면·기존 전체 회귀 테스트와 문서 갱신

## 최종 결과 요약

- 1,083행이던 `SttBenchmarkScreen.kt`는 신규 `TranscriptionRoute`를 호출하는 25행 호환 wrapper로 축소했다.
- 전사·보관함·설정 route를 stateless screen과 route ViewModel로 분리하고 dialog/선택 상태를 `SavedStateHandle`에 저장했다.
- 모델 설치·삭제, Codex 계정, 기기 정보와 개발 진단은 설정으로 이동했으며 성능 기록은 Debug 빌드에서만 노출한다.
- 보관함은 stable session/group ID와 audio path로 dialog 대상을 복원하고 사라진 대상은 안전하게 dismiss한다.
- Debug intent/broadcast 자동화는 별도 요청 계약을 거쳐 신규 전사 route로 연결했다.
- 실기기 화면 검수에서 숨은 구 `audioPaths`와 표시 오디오의 불일치를 발견했고, 표시 중인 `audioPath`를 실행 가능 여부와 실행 대상의 유일한 기준으로 수정했다.
- JVM/Robolectric/Compose 테스트 95개가 모두 통과했다. Samsung 계측 테스트는 10개 통과, AICore opt-in 1개 skip이며 실패는 없다.

- Samsung SM-S931N Android 16에서 최종 cold start 471ms, fatal/crash 없음, 잔류 Recorder/STT service 없음, active wake lock 0을 확인했다.
