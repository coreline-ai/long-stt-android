# 녹음 입력 장치 전환 안정성 구현 계획

## 목적

- 녹음 중 Bluetooth/USB/유선/내장 마이크 경로가 바뀌어도 기존 청크를 먼저 안전하게 확정하고 새 청크에서 녹음을 이어간다.
- 입력 장치 전환 사실과 처리 상태를 녹음 화면에서 확인할 수 있게 한다.
- 실제 장치명·식별자·오디오 내용은 checkpoint, 로그, GUI에 남기지 않는다.

## 범위

### 포함

- 일반 입력 분류 간 전환을 판정하는 순수 정책
- 현재 청크와 일치하는 장치 전환 명령을 `RecorderCommandActor`에서 직렬 처리
- 기존 청크 확정 후 다음 청크 preflight 및 재시작
- 장치 전환 후 녹음 화면 상태 메시지 유지
- 중복·지연 콜백과 예약 rollover 경쟁 회귀 테스트
- 자동 테스트, lint, debug/release 빌드와 안전한 실기기 smoke

### 제외

- 실제 Bluetooth/USB 장치 연결·해제 자동 수행
- 전화·알람을 실제로 발생시키는 interruption 검증
- 오디오 포커스 정책 변경 또는 앱 전체 navigation 재작성
- 실제 계정 로그인, 외부 LLM 요청, 외부 앱 최종 전송
- 기존 사용자 데이터 삭제, 앱 초기화, uninstall

## 엔지니어링 검토

### 결론

- **조건부 승인**: 라우팅 콜백 자체에서 backend를 직접 중지하지 않고 actor mailbox에 명령을 넣어 기존 START/STOP/rollover 직렬화 계약을 유지한다.

### 데이터 흐름

1. backend가 장치 ID 없이 `RecordingInputRoute` 일반 분류만 보고한다.
2. 최초 `UNKNOWN -> 실제 입력`과 동일 입력 반복은 관찰만 한다.
3. `RECORDING` 중 이미 확인된 입력이 달라지면 현재 session/chunk를 담은 전환 명령을 제출한다.
4. actor가 명령의 session/chunk 최신성을 검증하고 기존 rollover 경로로 현재 파일을 확정한다.
5. 다음 청크 시작 preflight가 성공하면 GUI에 안전 전환 메시지를 유지하고 녹음을 계속한다.
6. 파일 확정 또는 다음 입력 시작이 실패하면 기존 terminal failure/recovery 계약으로 종료한다.

### 주요 위험과 완화

- 콜백 폭주: 최초 관찰·동일 값은 무시하고 session/chunk 최신성 검증으로 청크당 유효 전환을 한 번만 처리한다.
- 예약 rollover 경쟁: 같은 mailbox에서 순서화하고 먼저 처리된 명령이 chunk index를 바꾸면 나머지는 stale로 무시한다.
- 지연 콜백: 기존 route epoch와 chunk 검증을 함께 유지한다.
- 무음/손상 파일: 변경 시 현재 파일을 먼저 검사·확정하고 새 backend preflight 실패는 명시적 실패로 전환한다.
- 개인정보 노출: 일반 분류 enum 외 장치명·ID를 전달하거나 저장하지 않는다.
- UX 과잉 알림: 시스템 dialog를 띄우지 않고 기존 녹음 상태 카드의 안내 문구를 사용한다.

## 완료 조건

- 장치 경로 변경은 actor에서 직렬화되고 이전 청크 확정 전 새 backend가 시작되지 않는다.
- 최초·중복·지연 콜백이 불필요한 연속 rollover를 만들지 않는다.
- GUI가 전환 사실을 표시하며 장치명·ID·파일 경로를 노출하지 않는다.
- 자동 검증과 안전한 실기기 smoke가 통과한다.
- 하드웨어 또는 사용자 조작이 필요한 검증은 통과로 처리하지 않는다.

## 구현·검증 결과

- 일반 입력 분류만 actor에서 직렬 처리하며 session/chunk/route epoch가 오래된 콜백은 무시한다.
- 확인된 경로가 달라지면 현재 청크를 먼저 확정하고 새 backend preflight를 거쳐 다음 청크를 시작한다.
- `UNKNOWN` 경로는 1.5초 동안 대체 입력을 기다려 transient callback으로 인한 불필요한 분할을 줄였다.
- 전환 안내는 ticker 이후에도 유지되고 기존 상태 카드의 polite live region과 200% 글자 scroll 테스트를 통과했다.
- 앱 252건, OAuth 43건, 총 295건 단위/Robolectric/Compose 테스트가 통과했다.
- Debug/Release lint, Debug/Release/deviceTest build, deviceTest AndroidTest, Release surface, asset provenance, unsigned AAB, 16KB alignment, `git diff --check`가 통과했다.
- Samsung SM-S931N의 격리 deviceTest는 비민감 8건 통과, 실마이크/AICore 5건 opt-in skip으로 완료됐다.
- 알림 권한이 거부된 기기에서 완료 알림 계측 setup assertion과 부분 초기화 teardown NPE를 발견해 테스트가 필요한 권한을 준비하고 null-safe cleanup하도록 수정했다.
- 최종 Debug APK는 `adb install -r -t`로 설치했고 MainActivity cold start와 Recorder/STT service 비활성을 확인했다.
- 계획 실행 시점의 자동·합성 결과는 위에 보존한다. 이후 2026-08-14 프로젝트 담당자가 실제 마이크 녹음, Bluetooth/USB route 변경, 전화·알람, 잠금 조작까지 완료한 것으로 확인했다. 민감한 원시 증적은 저장소에 기록하지 않으며, 최신 상태는 [`VERIFICATION_COMPLETION_20260814.md`](../docs/VERIFICATION_COMPLETION_20260814.md)를 따른다.
