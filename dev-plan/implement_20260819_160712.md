# implement_20260819_160712.md

작성 일시: `2026-08-19 16:07:12 KST`

이 문서는 개인 사용자가 최초 한 번 Google Drive 권한을 승인한 뒤 완료 전사와 저장된 최종 요약을 앱에서 직접 업로드하고, 직접 업로드가 불가능할 때 Drive 앱 공유 화면으로 안전하게 전달하는 개발 범위를 고정한다.

## 개발 목적

- 개인 사용자의 Google Drive에 완료 전사와 저장된 최종 요약을 앱에서 직접 업로드한다.
- 최초 Google 권한 승인 뒤에는 파일 선택기 없이 수동 1회 탭 업로드와 사용자 선택 자동 업로드를 지원한다.
- 앱 서버, Firebase Storage, 서비스 계정 없이 Google Drive API를 사용자 권한으로 직접 호출한다.
- 인증 만료·네트워크 중단·프로세스 재생성·중복 실행을 안전하게 복구하고 진행 상태를 보관함과 설정에서 확인한다.
- 직접 업로드를 사용할 수 없을 때 기존 `content://` 파일 공유 계약으로 Drive 앱을 포함한 시스템 공유 화면에 전달한다.
- 기존 전체 보기·TXT 저장·파일 공유·외부 요약·요약 공유·전사 채팅과 로컬 우선 보안 경계를 회귀시키지 않는다.

## 문서 기반 제약 사항

- Drive 직접 업로드는 완료 단일 전사 또는 전체 완료·비부분 녹음 그룹만 대상으로 한다.
- 요약은 `SummarySessionStore.Entry`에 실제 저장된 최종 요약만 업로드하며 진행 중·오류·임시 요약은 업로드하지 않는다.
- 자동 업로드 기본값은 `OFF`이며 사용자가 업로드 내용·시점·외부 전송 사실을 확인하고 직접 켠 뒤에만 동작한다.
- 자동 업로드를 켜기 전의 기존 보관함 항목은 자동 백필하지 않고 상세의 수동 업로드만 제공한다.
- Google 인증은 ChatGPT/Codex OAuth와 별도 책임·저장소·UI를 사용한다.
- 액세스 token과 Google 계정 식별자는 일반 preferences, WorkManager `Data`, 로그, 문서, 스크린샷에 저장하거나 출력하지 않는다.
- Google Play services가 관리하는 token을 앱이 별도 refresh token으로 복제하지 않는다.
- Worker 입력에는 불투명 `jobId`만 넣고 source type/ID, Drive file/folder ID, 전사·요약문은 앱 private store에서만 해석한다.
- Drive resumable session URI는 bearer capability로 취급해 로그에 남기지 않고, 재개를 위해 보존할 경우 별도 Android Keystore alias로 암호화한다.
- Drive의 폴더명·파일명·description·`appProperties`에는 전사 제목, note, 원본 파일명, source ID를 넣지 않는다.
- 원격 중복 판별에는 source ID 대신 앱 private store가 발급한 불투명 `exportId`와 파일 kind만 사용한다.
- 전사 파일은 기존 `TranscriptExportWriter`를 재사용해 전용 `cache/drive_exports` 아래에 스트리밍 생성한다.
- 업로드 완료·실패·취소 뒤 임시 파일 정리는 `cache/drive_exports` 아래 앱 소유 파일에만 적용한다.
- 실제 Google 로그인과 Drive 전송 검증에는 사용자 승인을 받은 비민감 합성 전사·요약만 사용한다.
- `.commandcode/`와 기존 사용자 변경사항은 수정·스테이징하지 않는다.

## 잔여 리스크 / 후속 과제

- Google Cloud Console의 OAuth 동의 화면, Android client, Debug·production signing fingerprint 등록은 저장소 코드만으로 완료할 수 없는 운영 작업이다.
- `drive.file`은 앱이 생성·허용받은 파일 범위만 제공하므로 사용자가 Drive에서 앱 폴더나 파일을 이동·삭제한 상태를 reconciliation해야 한다.
- WorkManager background 실행 시점은 Android 전원·네트워크 정책에 따라 지연될 수 있으며 GUI는 `대기`와 `실행`을 구분해야 한다.
- 실제 Google 계정 다중 선택, 권한 철회, quota 정책은 비민감 테스트 계정과 사용자 승인 실기기 검증 없이는 최종 통과로 처리하지 않는다.
- 자동 업로드는 사용자 opt-in 이후에도 민감 전사·요약을 외부에 복제하므로 설정과 상세에서 언제든 상태·중지·연결 해제를 확인할 수 있어야 한다.
