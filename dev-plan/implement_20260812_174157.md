# implement_20260812_174157.md

작성 일시: `2026-08-12 17:41:57 KST`

이 문서는 완료 결과 CTA의 프로세스 재시작 복원과 완료 알림 딥링크를 구현하고, 남은 P0 실기기 흐름을 검증하는 범위를 고정한다.

## 개발 목적

- 단일 전사 또는 녹음 그룹 완료 target을 원문 없이 앱 private storage에 보존한다.
- 앱 프로세스 재시작 뒤에도 전사 화면에서 완료 결과 CTA를 복원한다.
- 완료 알림을 누르면 보관함의 정확한 완료 결과 상세를 연다.
- 합성 입력과 비민감 UI 상태만 사용해 완료 CTA·요약 공유 취소·200% 글자 흐름을 실기기에서 검증한다.

## 개발 범위

- type/ID만 저장하는 실패 폐쇄형 완료 target 저장소
- 단일 완료와 완료/부분 완료 녹음 그룹의 Service terminal 저장
- 새 전사·새 입력·대상 삭제 시 저장 target 제거
- cold start 라이브러리 로딩 완료 후 target 검증·복원
- 별도 완료 알림과 immutable explicit PendingIntent
- MainActivity notification intent와 Compose 일회성 보관함 상세 이동
- 프로세스 재시작, 손상/삭제 target, 중복 클릭·회전 회귀 테스트
- Samsung SM-S931N 합성 전사, 공유 chooser 취소, 200% 글자·좁은 화면 검증

## 제외 범위

- 전사 완료 즉시 강제 화면 이동
- 최신 결과/수정 시각으로 target을 추정하는 복구
- 전사 원문·요약문·파일 경로·note·OAuth 값을 target 저장소나 알림에 저장
- 외부 앱 자동 선택·실제 발송, 특정 공유 앱 강제 지정
- 기존 전사·요약·녹음·모델 삭제, `pm clear`, `adb uninstall`
- Git commit·push

## 문서 기반 제약 사항

- 완료 결과 정본은 `TranscriptionSessionStore.Checkpoint`와 `RecordingTranscriptionGroupStore.Group`이다.
- 저장소와 Intent에는 허용된 type/ID만 기록하며 잘못된 형식은 즉시 폐기한다.
- cold start에서는 결과 라이브러리 첫 로딩이 끝난 뒤 target 유효성을 판정한다.
- 누락·삭제·손상 target은 보관함 최신 결과를 대신 열지 않고 목록으로 폴백한다.
- 진행 foreground 알림과 완료 알림 ID를 분리하며 새 전사 시작 시 이전 완료 알림을 제거한다.
- 실기기 검증은 합성 오디오 이름과 일반 상태 문구만 확인하고 전사/요약 payload는 읽거나 출력하지 않는다.
