# implement_20260807_144941.md

작성 일시: `2026-08-07 14:49:41 KST`

이 문서는 Galaxy S25에서 전사 완료된 장문 한국어 텍스트를 외부 서버로 보내지 않고 빠르게 요약하는 개발 범위를 고정한다.

## 개발 목적

현재 `TranscriptionSessionStore`에 보관된 완료 전사 결과를 Google ML Kit GenAI Summarization API로 온디바이스 요약한다. 16만 자처럼 요청 한도를 넘는 입력은 타임스탬프 세그먼트 단위로 분할하고, 구간 요약을 계층적으로 다시 요약해 최종 1~3개 핵심 항목과 시간대별 구간 요약을 제공한다.

1차 합격 기준은 삼성 SM-S931N에서 한국어 요약 기능을 실제로 사용할 수 있고, 전사 파이프라인과 동시에 실행되지 않으며, 중단 후 완료된 요약 단위부터 재개되고, 원문·요약이 외부 요약 서버로 전송되지 않는 것이다.

## 문서 기반 제약 사항

- Galaxy S25는 공식 feature-specific Summarization API 지원 목록에 포함되지만 실제 사용 가능 여부는 매 실행 전에 `checkFeatureStatus()`로 판정한다.
- 요약 API 입력은 4,000토큰 미만이며 자동 잘라내기는 전체 coverage를 잃으므로 사용하지 않는다.
- 출력은 최대 3개 bullet이며 상세 장문 생성 기능으로 과장하지 않는다.
- GenAI API는 앱이 최상위 foreground일 때만 실행할 수 있다. 화면 이탈 시 현재 호출을 취소하고 checkpoint 이후부터 재개한다.
- `BUSY`, 배터리 quota, 기능 다운로드 필요, 기능 미지원, 부트로더 unlock을 서로 다른 상태로 표시한다.
- 현재 전사에는 화자 라벨이 없으므로 `CONVERSATION` 형식을 만들기 위해 가짜 화자를 추가하지 않는다.
- ML Kit가 공개 토크나이저를 제공하지 않는 경우 보수적 문자 예산과 `REQUEST_TOO_LARGE` 재분할을 함께 사용한다.
- 6시간 STT가 `PREPARING/RUNNING/COOLING`인 동안 요약을 시작하지 않는다.
- 현재 실행 중인 전사가 있다면 APK 재설치는 전사 완료 또는 안전 checkpoint 확인 후에만 수행한다.

## 아키텍처와 책임 경계

```text
TranscriptionSessionStore(COMPLETED)
        ↓ 세그먼트·타임스탬프
SummaryPlanner ── 입력 단위/병합 단계 계산
        ↓
OnDeviceSummarizer ── ML Kit 호출·기능 상태·오류 변환
        ↓
SummaryCoordinator ── 순차 실행·재시도·계층 병합·취소
        ↓
SummarySessionStore ── 원자 checkpoint·결과 보관
        ↓
SummaryViewModel / Compose UI
```

- `SummaryPlanner`: Android/ML Kit에 의존하지 않는 순수 분할·병합 계획만 담당한다.
- `OnDeviceSummarizer`: ML Kit SDK를 감싸고 앱 내부 오류 계약으로 변환한다. 저장·UI 책임을 갖지 않는다.
- `SummaryCoordinator`: 한 번에 하나의 AICore 요청만 실행하고 상태 전이를 관리한다.
- `SummarySessionStore`: 전사 원문을 복제하지 않고 source session ID·hash·세그먼트 범위·생성 요약만 저장한다.
- `SummaryViewModel`: 화면 수명과 foreground 조건을 연결하고 전사 ViewModel에 요약 로직을 추가하지 않는다.
- `DeviceWorkCoordinator`: STT·모델 로드·요약이 동시에 기기 추론 자원을 사용하지 않도록 상호 배제한다.

## 데이터 계약

- 요약 세션 상태: `PREPARING`, `WAITING_FOR_MODEL`, `SUMMARIZING_UNITS`, `MERGING`, `FINALIZING`, `PAUSED`, `COMPLETED`, `FAILED`, `CANCELLED`, `STALE`
- source 식별: `sourceSessionId`, source text SHA-256, source updatedAt
- 단위 결과: index, source segment 시작/끝 index, start/end ms, input hash, status, attempt, bullets, error
- 병합 결과: level, group index, child IDs, status, bullets
- 실행 정보: AICore base model name, SDK version, created/updated time, active elapsed time
- 최종 결과: 최대 3개 핵심 bullet과 시간대별 1차 단위 요약
- 저장 위치: `files/summary_sessions/<summaryId>.json`, `AtomicFile` 사용
- source 전사 삭제 시 연결 요약 수를 알리고 확인 후 함께 삭제한다.

## Phase 2. 입력 계획·요약 저장 기반

### 목표

16만 자 원문을 누락 없이 처리할 수 있는 결정적 분할 계획과 재개 가능한 별도 요약 저장소를 만든다.

### 구현 태스크

- [ ] 완료 전사 checkpoint의 ordered segments를 source-of-truth로 사용한다.
- [ ] 빈 세그먼트와 공백을 제외하되 원본 segment index와 start/end ms를 보존한다.
- [ ] Phase 1에서 확정한 문자 예산 안에서 인접 세그먼트를 1차 단위로 묶는다.
- [ ] 400자 미만 tail은 앞 단위와 결합하고 과대한 단일 세그먼트는 문장/공백 경계로 안전 분할한다.
- [ ] `REQUEST_TOO_LARGE` 발생 시 해당 단위만 세그먼트 중간에서 이분하고 종료 조건을 둔다.
- [ ] 1차 bullet들을 다시 입력 예산 안에서 그룹화하는 다단계 merge plan을 구현한다.
- [ ] source hash·prompt/options version·AICore model name을 포함하는 요약 세션 schema를 정의한다.
- [ ] `SummarySessionStore`에 생성·저장·로드·목록·삭제와 schema version 처리를 구현한다.
- [ ] 단위 완료마다 전체 요약 전문이 아닌 생성 결과와 source 범위만 `AtomicFile`로 저장한다.

## Phase 3. 순차 계층 요약·복구
