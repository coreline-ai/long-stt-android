## 개발 목적

완료된 6시간 STT 결과를 현재 전사 안정성을 침해하지 않고 외부 Codex 계정으로 계층 요약한다. Android에는 ChatGPT/Codex 토큰을 저장하지 않고, 자체 `Summary Gateway`가 공식 `codex app-server`를 stdio로 제어하며 device-code 로그인 화면을 Android에 제공한다.

1차 합격 기준은 삼성 SM-S931N에서 완료된 `38/38` 청크·`166,870`자 전사를 `13`개 약 30분 단위로 빠짐없이 처리하고, 단위 요약·병합·최종 요약을 중단 후 재개하며, 기존 6시간 STT 경로와 checkpoint를 변경하거나 손상하지 않는 것이다.

## 확정 구현 방향

```text
TranscriptionSessionStore (COMPLETED + coverage 100%)
        ↓ ordered chunks/segments, sourceContentSha256
SummaryInputPlanner (38 chunks → 13 units)
        ↓ 한 단위씩 HTTPS, idempotency key
Summary Gateway (기기 인증·작업 상태·제한·감사 이벤트)
        ↓ 내부 JSONL/stdin·stdout, 외부 공개 금지
codex app-server (ChatGPT managed OAuth/device code)
        ↓ outputSchema JSON
SummarySessionStore (단위 즉시 원자 저장)
        ↓
merge 1회 → final 1회 → Summary UI
```

- Android는 Gateway 로그인 토큰만 보관하며 OpenAI/ChatGPT 토큰은 보거나 받지 않는다.
- app-server가 ChatGPT OAuth 토큰 저장·갱신을 소유하고 Gateway는 `account/*` 결과만 중계한다.
- Android가 13개 단위를 순차 전송한다. Gateway는 활성 추론 중에만 원문을 메모리에 유지하고 DB·일반 로그에 원문을 저장하지 않는다.
- 각 단위는 새 app-server thread에서 처리하고 완료·실패 후 `thread/delete`로 정리한다.
- Android가 결과 checkpoint의 최종 source-of-truth다. Gateway DB에는 작업 식별자·해시·상태·구조화 출력·측정값만 저장한다.
- app-server remote WebSocket은 사용하지 않고 Gateway 자식 프로세스의 stdio JSONL만 사용한다.

참조 저장소의 루트 라이선스가 미선언 상태이므로 owner가 내부 코드 재사용을 명시하기 전에는 원문 코드를 복사하지 않는다. 위 표의 적용 항목은 동작·보안 패턴을 현재 프로젝트 명명과 테스트 계약으로 재구현한다.

## API 및 데이터 계약

### Android → Summary Gateway

- `POST /v1/device-pairings/exchange`: 1회용 pairing code를 access/refresh token으로 교환
- `POST /v1/device-sessions/refresh`: 회전형 refresh token으로 access token 갱신
- `DELETE /v1/device-sessions/current`: 현재 기기 연결 해제
- `GET /v1/codex/account`: `SIGNED_OUT/LOGIN_PENDING/SIGNED_IN/REAUTH_REQUIRED` 반환
- `POST /v1/codex/device-logins`: device-code 로그인 시작
- `GET /v1/codex/device-logins/{loginId}`: 완료·실패 상태 조회
- `DELETE /v1/codex/device-logins/{loginId}`: 로그인 취소
- `POST /v1/summary-jobs`: `UNIT/MERGE/FINAL` 비동기 작업 생성
- `GET /v1/summary-jobs/{jobId}`: 상태·결과·사용량 조회
- `POST /v1/summary-jobs/{jobId}/cancel`: 실행 중 turn 중단

### Gateway 작업 상태

- `QUEUED`, `AUTH_REQUIRED`, `RUNNING`, `SUCCEEDED`, `FAILED_RETRYABLE`, `FAILED_FINAL`, `CANCELLED`
- 모든 생성 요청에 `Idempotency-Key`와 canonical request SHA-256을 저장한다.
- 같은 사용자·같은 key·같은 hash는 기존 작업을 반환하고, 같은 key·다른 hash는 `409`를 반환한다.
- 입력 body는 기본 `1 MiB`, 단일 unit text는 기본 `256 KiB`, 결과는 `8 MiB` 이하로 제한한다.
- Gateway 응답은 고정 오류 코드와 `retryable`만 노출하고 provider 예외 전문·토큰·원문을 반환하지 않는다.

### Android SummarySession

- 상태: `PREPARING`, `WAITING_FOR_AUTH`, `SUMMARIZING_UNITS`, `MERGING`, `FINALIZING`, `PAUSED`, `COMPLETED`, `FAILED`, `CANCELLED`, `STALE`
- source: `sourceSessionId`, `checkpointFileSha256`, `sourceContentSha256`, `durationMs`, `totalChunks`, `totalSegments`
- 버전: `schemaVersion`, `plannerVersion`, `promptVersion`, `unitOutputSchemaVersion`, `mergeOutputSchemaVersion`, `finalOutputSchemaVersion`
- 단위: `index`, `startChunkIndex`, `endChunkIndex`, `startMs`, `endMs`, `inputSha256`, `idempotencyKey`, `gatewayJobId`, `status`, `attempt`, `result`, `errorCode`
- 실행: `requestedAtMs`, `startedAtMs`, `completedAtMs`, `activeElapsedMs`, `retryCount`, `inputTokens`, `outputTokens`, `model`, `requestId`
- 저장: `files/summary_sessions/<summaryId>.json`, `AtomicFile`
- `sourceContentSha256`는 정렬된 청크/세그먼트의 index·start/end ms·UTF-8 text를 canonical JSON으로 만든 뒤 계산한다. checkpoint 파일 자체 해시와 혼용하지 않는다.

## 보안·운영 경계

- Gateway release 경로는 HTTPS만 허용하고 Android cleartext traffic은 debug 전용으로 제한한다.
- app-server는 `127.0.0.1` TCP에도 노출하지 않고 자식 프로세스 stdio만 연결한다.
- Gateway의 `CODEX_HOME`은 전용 OS 사용자와 권한 `0700` 디렉터리에 둔다.
- Android pairing code는 10분 이내 1회 사용, access token은 15분, refresh token은 회전·폐기 가능하게 구현한다.
- Android refresh token은 Keystore AES-GCM으로 저장하고 access token은 프로세스 메모리에만 둔다.
- `turn/start`는 빈 격리 작업 디렉터리, `approvalPolicy=never`, 제한된 read-only sandbox, `outputSchema`를 사용한다.
- command/file change/tool 실행 item 또는 server approval request가 나타나면 현재 turn을 중단하고 정책 위반으로 실패 처리한다.
- 전사 원문·요약 전문·인증 코드·토큰·provider URL은 logcat/Gateway 일반 로그/진단 이벤트에 넣지 않는다.
- 사용자가 매 요약 전에 외부 전송 범위와 서버 주소를 확인하고 명시적으로 동의해야 한다.
- 현재 app-server 방식은 내부 단일 사용자 실험으로 한정한다. 공개 배포는 OpenAI 정책·계정 사용 방식·운영 지원 여부를 별도 승인받은 뒤 진행한다.

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 기록한다.

- 문서에 없는 범위 확장은 하지 않는다.
- 요구사항이 불명확하면 가능한 케이스를 나누고 확인 후 진행한다.
- 한 기능은 유지보수 가능한 최소 책임 단위로 나누고 각 단위의 역할과 경계를 지킨다.
- 기존 전사 checkpoint는 읽기 전용 source로 취급하고 요약 때문에 다시 저장하지 않는다.
- 6시간 STT가 `PREPARING/RUNNING/COOLING`이면 요약 시작과 Gateway 전송을 차단한다.
- 자동 retry는 idempotency와 실패 시점이 명확한 작업에만 허용한다.
- 모델 ID는 Gateway 설정으로 고정하고 Android 하드코딩·사용자 임의 입력을 허용하지 않는다.
- app-server 버전별 schema를 생성·고정하고 schema를 다시 생성하지 않은 버전 업그레이드는 금지한다.
- 새 Android 의존성은 현재 Kotlin 1.9.22/compileSdk 34와 실제 빌드 호환성을 먼저 검증한다.
- 원문과 생성 결과를 테스트 fixture에 넣을 때 실제 개인정보를 제거한다.
