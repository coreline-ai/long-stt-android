## 개발 목적

실제 삼성폰에서 OAuth 로그인과 Codex 챗봇 응답이 검증된 `alpine-llm-gateway`의 Android 경로를 현재 STT 앱에 직접 포팅한다. 동일한 `Custom Tabs → localhost:1455 loopback → Authorization Code + PKCE → token 교환 → Android Keystore 저장 → Codex Responses SSE` 흐름을 먼저 재현한 뒤, 완료된 6시간 전사를 13개 구간으로 계층 요약한다.

1차 합격 기준은 SM-S931N에서 기존과 동일한 Codex 계정 로그인이 성공하고 비민감 단일 요청이 응답한 뒤, 현재 `38/38` 청크·`166,870`자 전사를 `13`개 구간 요약 → 병합 → 최종 요약까지 중단·재개 가능하게 완주하며 기존 6시간 STT checkpoint를 변경하지 않는 것이다.

이 문서는 [Gateway/app-server 방식 계획](implement_20260807_163104.md)을 대체한다. 별도 서버를 먼저 만드는 이전 방향은 실제 Android OAuth·Codex E2E 성공 증거가 없다는 가정에 기반했으나, 사용자가 기존 앱의 실계정 성공을 확인했고 참조 저장소에도 삼성폰 실제 응답 증거가 있으므로 직접 포팅으로 변경한다.

## 확정 아키텍처

```text
MainActivity / Summary UI
        ↓ 로그인·로그아웃·상태만 요청
CodexSummaryAuthController
        ↓
:codex-oauth-android
  OAuthManager ── Custom Tabs + localhost:1455 + PKCE/state
  OAuthTokenStore ── Android Keystore AES-GCM
  OAuthLlmSession ── 만료 refresh / 401 refresh 1회
  CodexResponsesOAuthAdapter
  UrlConnectionOAuthHttpTransport ── HTTPS/SSE/취소/size limits
        ↓
chatgpt.com Codex Responses

TranscriptionSessionStore(COMPLETED)
        ↓ ordered chunks/segments
SummaryInputPlanner (38 chunks → 13 units)
        ↓ 한 번에 하나
CodexSummaryClient / ExternalSummaryCoordinator
        ↓ unit 즉시 저장
SummarySessionStore(AtomicFile)
        ↓
merge → final → SummaryScreen
```

- OAuth 저수준 코드는 `:codex-oauth-android`가 소유하고 STT·Compose UI에 token을 노출하지 않는다.
- 앱 계층은 고정 profile ID, 허용 모델, 요약 prompt/schema, state machine만 소유한다.
- `TranscriptionSessionStore`는 source-of-truth이며 요약 때문에 다시 저장하지 않는다.
- `SummarySessionStore`는 source 전문을 복제하지 않고 source hash·범위·생성 결과·측정값만 저장한다.
- 전체 추론 동시성은 1개다. STT가 활성 상태면 인증을 제외한 요약 요청을 시작하지 않는다.

## OAuth·요약 데이터 계약

### OAuth 상태

- `SIGNED_OUT`
- `AUTHORIZING`
- `AUTHENTICATED(expiresAtMs, displayMetadata)`
- `REAUTHENTICATION_REQUIRED(reason)`
- `FAILED(kind)`

고정 provider ID는 `codex_summary_v1`로 유지한다. 모델을 바꾸어도 token key와 OAuth registration은 변경하지 않는다.

### SummarySession

- 상태: `PREPARING`, `WAITING_FOR_AUTH`, `SUMMARIZING_UNITS`, `MERGING`, `FINALIZING`, `PAUSED`, `COMPLETED`, `FAILED`, `CANCELLED`, `STALE`
- source: `sourceSessionId`, `checkpointFileSha256`, `sourceContentSha256`, `durationMs`, `totalChunks`, `totalSegments`
- 버전: `schemaVersion`, `plannerVersion`, `promptVersion`, `unitSchemaVersion`, `mergeSchemaVersion`, `finalSchemaVersion`
- unit: `index`, `startChunkIndex`, `endChunkIndex`, `startMs`, `endMs`, `inputSha256`, `status`, `attempt`, `result`, `errorCode`
- 호출: `model`, `requestedAtMs`, `startedAtMs`, `completedAtMs`, `inputTokens`, `outputTokens`, `requestId`, `finishReason`
- 저장: `files/summary_sessions/<summaryId>.json`, `AtomicFile`

### Codex 요청

- `model`: 사용자가 허용 목록에서 선택한 값
- `system`: versioned 요약 시스템 지시
- `messages`: 도구 없는 `user` text 1개
- `tools`: 보내지 않음
- `stream`: adapter가 stage 실행에 맞게 설정
- provider body는 기존 adapter의 `store=false`, fixed endpoint, fixed headers를 유지
- unit/merge/final 출력은 prompt의 JSON 계약으로 제한하고 앱에서 schema를 검증한다.
- 현재 adapter가 `response_format`과 `max_output_tokens`를 전달하지 않으므로 MVP는 이를 지원한다고 가정하지 않는다. prompt+validator+최대 1회 교정으로 처리한다.

## 보안·호환 경계

- access/refresh token, authorization code, PKCE verifier, state를 logcat·UI·Intent·summary JSON에 넣지 않는다.
- profile UI에서 endpoint/client ID/scope/callback을 수정할 수 없게 한다.
- `OAuthRedirectActivity`는 exported 상태를 유지하되 활성 port/path/state registry가 일치할 때만 loopback으로 전달한다.
- callback server는 `127.0.0.1` backlog 1, path 고정, request/header limit을 유지한다.
- Codex token은 fixed token endpoint에만, access token은 fixed Responses endpoint에만 보낸다.
- source의 account ID metadata 추출은 기존 성공 경로 호환을 위해 유지하되 앱의 사용자 인증·권한 판단에는 사용하지 않고 Provider header 주입에만 사용한다.
- inference POST는 명시적 idempotency 계약이 없으므로 transport 자동 retry를 금지한다.
- OAuth token 교환은 source와 동일하게 network transport 오류만 최대 3회 재시도한다.
- 요약 원문은 한 unit씩 메모리에서 요청하고 로그나 OAuth 저장소에 복제하지 않는다.
- 외부 전송 직전에 source 범위·글자 수·선택 모델을 표시하고 사용자 동의를 받는다.
- upstream endpoint/header/model 변경으로 실패하면 summary 진입점만 비활성화하고 STT 기능은 유지한다.

## 잔여 리스크 / 후속 과제

- Codex account endpoint·CLI fingerprint·model 목록은 upstream 변경으로 깨질 수 있으므로 capability probe와 빠른 UI 비활성화 경로가 필요하다.
- 현재 account ID는 token 응답의 JWT claim metadata에서 추출하며 서명 검증을 앱에서 수행하지 않는다. Provider header 호환에만 제한하고, 장기적으로 issuer/audience/nonce/JWKS 검증을 별도 검토한다.
- 현재 adapter는 `max_output_tokens`, `response_format`, strict structured output을 전달하지 않는다. 6시간 품질 gate 결과에 따라 adapter 확장 가능성을 별도 검토한다.
- 공개 배포 정책과 client registration 재사용 범위는 실제 내부 동작 여부와 별도 문제이므로 출시 전 확인한다.
- TXT/MD/PDF export와 외부 문서 import는 `implement_20260807_161201.md` 완료 후 Summary `DocumentSnapshot`을 연결한다.
