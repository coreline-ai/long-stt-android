# LongSTT Android 개발 핸드오프

최초 작성: `2026-08-07 16:47:17 KST`
최종 갱신: `2026-08-07 20:08 KST`

이 문서는 현재 저장소, 삼성폰, 6시간 전사 데이터, 미완료 계획과 다음 구현 순서를 한곳에 고정한다. 체크된 개발 계획만 믿지 말고 아래의 `실제 확인`, `계획`, `미검증` 구분을 유지한다.

## 1. 현재 결론

- 프로젝트의 1차 목적은 삼성폰에서 6시간급 WAV/M4A/MP3 전사를 누락 없이 완주하고 결과를 안전하게 보존하는 것이다.
- 장시간 STT, 10분 청크 처리, Foreground Service, checkpoint, 전사 결과 보관함, 오디오·Whisper 모델 관리 코드는 현재 앱에 존재한다.
- 삼성 SM-S931N에는 최신 Debug `com.stt.benchmark` 1.0.0이 클린 설치되어 있고 설치 APK hash가 로컬 산출물과 일치한다.
- 사용자의 명시적 승인으로 이전 앱과 앱 데이터를 삭제했다. 완료된 6시간 checkpoint는 기기가 아니라 Git 제외 로컬 백업에만 보존된다.
- STT 안정화 빌드는 빈 앱 데이터로 콜드 스타트했으며 활성 `TranscriptionService`와 crash가 없다.
- Codex OAuth source parity는 독립 `:codex-oauth-android` 모듈로 이식되어 43/43 JVM과 Samsung Keystore 2/2 계측을 통과했다.
- 다음 개발은 앱 wrapper/GUI를 연결하는 실제 OAuth login/restore/refresh/logout parity다. 외부 LLM 요약 데이터 계층은 아직 구현하지 않는다.
- 별도 Gateway와 `codex app-server`를 먼저 만드는 계획은 폐기하지 않고 이력으로만 보존하며, 현재 실행 계획으로 사용하지 않는다.
- 온디바이스 AICore/ML Kit 요약은 현재 삼성폰에서 사용할 수 없음이 확인되어 정식 경로로 진행하지 않는다. 관련 코드는 debug/androidTest 사전 probe일 뿐이다.

## 5. 현재 앱에 실제 구현된 기능

### STT 실행

- `MainActivity`가 일반 실행과 ADB 자동 실행 extra를 `SttViewModel`로 전달한다.
- `WhisperCppEngine`이 모델 로드, PCM 전사, segment 결과, native release를 담당한다.
- `AudioDecoder`가 WAV와 Android `MediaExtractor/MediaCodec` 기반 압축 오디오 구간 디코딩을 담당한다.
- 메인 장시간 경로는 `TranscriptionService`에서 실행된다.
- 서비스는 `START_STICKY`, Foreground notification, partial WakeLock을 사용한다.
- 기본 청크는 10분이다.
- 청크 양쪽에 1초 overlap을 디코딩하고 primary 시간 범위의 segment만 결과에 포함한다.
- 청크 실패는 최대 2회 시도한다.
- 청크 사이 기본 냉각은 10초이고 5번째 청크마다 30초 냉각한다.
- 실행 전 앱 내부 여유 공간 256MiB 이상을 요구한다.
- 처리 완료 후 coverage를 검증하며 허용 오차는 50ms다.

- [`MainActivity.kt`](../app/src/main/java/com/stt/benchmark/MainActivity.kt)
- [`SttViewModel.kt`](../app/src/main/java/com/stt/benchmark/ui/SttViewModel.kt)
- [`TranscriptionService.kt`](../app/src/main/java/com/stt/benchmark/service/TranscriptionService.kt)
- [`WhisperEngine.kt`](../app/src/main/java/com/stt/benchmark/whisper/WhisperEngine.kt)

### Checkpoint와 전사 결과

- `TranscriptionSessionStore`가 `files/stt_sessions/<sessionId>.json`에 저장한다.
- 상태는 `PREPARING`, `RUNNING`, `COOLING`, `COMPLETED`, `FAILED`, `CANCELLED`, `INTERRUPTED`다.
- 청크별 primary/decoded 범위, sample 수, retry, elapsed, text, segment를 저장한다.
- 저장에는 Android `AtomicFile`을 사용한다.
- 앱 재진입 시 최신 미완료 세션을 찾아 Foreground Service로 재개한다.
- 결과 보관함은 session JSON을 기준으로 조회하고, 활성/재개 대상이 아닌 결과는 삭제할 수 있다.
- CSV는 전사 본문의 source-of-truth가 아니라 별도의 성능 측정 기록이다.

### 오디오와 모델 관리

- 가져온 오디오는 앱 내부 저장소로 복사하고 `media_library.json`에 메타데이터와 선택 상태를 원자 저장한다.

- tiny, base, base-q5_1, small, small-q5_1, medium 모델 목록이 있다.

## 7. Git 작업 트리 상태

현재 브랜치는 `main`이고 원격 `origin/main`과 같은 초기 커밋을 가리킨다. 아래 변경은 아직 커밋되지 않았다.

```text
 M app/build.gradle.kts
?? app/src/androidTest/
?? app/src/debug/
?? dev-plan/implement_20260807_144941.md
?? dev-plan/implement_20260807_161201.md
?? dev-plan/implement_20260807_163104.md
?? dev-plan/implement_20260807_164038.md
?? docs/EXTERNAL_LLM_SUMMARY_6H.md
?? docs/HANDOFF_20260807.md
```

주의 사항:

- 기존 변경을 `git reset`, `git clean`, `git checkout --`로 지우지 않는다.
- `app/build.gradle.kts`, `app/src/debug`, `app/src/androidTest`는 AICore/ML Kit 사전 검증 작업이다.
- ML Kit summarization 의존성은 `androidTestImplementation`에만 있다. 정식 앱 기능으로 승격하지 않는다.
- 새 OAuth 작업은 위 변경과 파일 소유권이 겹치지 않도록 별도 library module부터 시작한다.
- 커밋 전에는 AICore probe 보존 여부와 OAuth Phase 1 변경을 논리적으로 분리하는 것이 좋다.

## 8. 요약 방식 결정 기록

### 온디바이스 요약

[온디바이스 계획](../dev-plan/implement_20260807_144941.md)의 Galaxy S25 probe는 실제 AICore 응답까지 도달했으나 Summarization feature가 provision되지 않아 한국어 모델 준비와 추론을 진행할 수 없었다.

- 현재 판정: 운영 기능으로 사용 불가
- probe 위치: `app/src/androidTest/.../OnDeviceSummaryProbeTest.java`
- debug 보조 Activity: `app/src/debug/.../SummaryProbeActivity.kt`
- 6시간 전사 checkpoint SHA-256은 probe 전후 동일했다.

### 외부 LLM 선행 요약

현재 Codex 작업 세션에서 6시간 전사를 38개 청크에서 약 30분 단위 13개로 나눠 전체를 읽고 계층 요약한 선행 결과가 있다. 정확한 전체 LLM 소요 시간은 기록하지 않았고, API key를 사용하는 OpenAI API 직접 호출도 하지 않았다.

- 기록과 프롬프트: [EXTERNAL_LLM_SUMMARY_6H.md](EXTERNAL_LLM_SUMMARY_6H.md)
- 재현 구조: 13개 unit 요약 → merge → final
- 앱 구현 시 unit별 checkpoint, source range, source hash, prompt/schema/model version, elapsed와 usage를 저장해야 한다.

### Codex OAuth 최종 방향

사용자는 `alpine-llm-gateway`의 기존 Android 앱에서 OAuth 로그인과 실제 Codex 챗봇 응답이 성공했음을 확인했다. 참조 README에도 삼성 SM-S931N 실제 검증 기록이 있다.

최종 판정은 `ready with parity gate`다.

- 활성 계획: [implement_20260807_164038.md](../dev-plan/implement_20260807_164038.md)
- 대체된 계획: [implement_20260807_163104.md](../dev-plan/implement_20260807_163104.md)
- 참조 저장소: `https://github.com/coreline-ai/alpine-llm-gateway.git`
- 고정 참조 commit: `3389fcbf92207bb632dac002d7bb501d0901ff22`
- 최초 parity 모델: `gpt-5.3-codex-spark`
- 고정 provider ID: `codex_summary_v1`
- 인증 흐름: Custom Tabs → localhost:1455 loopback → Authorization Code + PKCE/state → form token 교환 → Android Keystore AES-GCM → Codex Responses SSE

참조 저장소는 핸드오프 직전 다음 작업이 성공했다.

```text
:android:testDebugUnitTest
:alpine-chat-provider-android:testDebugUnitTest
:demo-chatbot:testDebugUnitTest
:demo-chatbot:assembleDebug

BUILD SUCCESSFUL in 35s
119 actionable tasks: 62 executed, 57 up-to-date
```

이는 참조 프로젝트의 빌드 증거다. 현재 STT 앱에서 OAuth 로그인이나 Codex 응답을 실행했다는 뜻은 아니다.

`2026-08-07 20:08 KST` 기준으로 참조 commit의 19개 production source와 43개 unit test를
`:codex-oauth-android`에 이식했다. package와 wire contract는 유지했고 Kotlin 1.9 호환 `else -> Unit`
1건만 적용했다. 세부 provenance와 공개 배포 blocker는
[`codex-oauth-android/UPSTREAM.md`](../codex-oauth-android/UPSTREAM.md)에 기록했다. 이는 source parity 완료이며,
현재 STT 앱에서 실제 OAuth가 동작한다는 뜻은 여전히 아니다.

## 9. 다음 구현 작업

반드시 활성 계획의 Phase 순서를 따른다.

### Phase 1 — OAuth 소스 독립 모듈 포팅 (기술 검증 완료)

아래 1~9 작업, 43개 JVM 테스트, Samsung Keystore 2개 계측, AAR/androidTest 조립, 앱 Debug 회귀를 완료했다.
upstream 루트 LICENSE가 없으므로 외부 배포/출시는 계속 차단한다.

1. `settings.gradle.kts`에 `:codex-oauth-android`를 추가한다.
2. compileSdk 34, minSdk 26, JVM 17의 Android library module을 만든다.
3. 참조 commit `3389fcb`의 Android OAuth/Codex 소스 19개를 package `dev.alpine.llm` 그대로 가져온다.
4. 참조 manifest의 `OAuthRedirectActivity`와 consumer rules를 가져온다.
5. Kotlin 2.2 AAR을 직접 사용하지 않고 현재 Kotlin 1.9.22/coroutines 1.7.3 환경에서 source를 재컴파일한다.
6. 현재 SDK와 호환되는 AndroidX Browser 버전을 실제 빌드로 고정한다.
7. upstream unit/instrumentation test를 포팅한다.
8. `codex-oauth-android/UPSTREAM.md`에 원본 commit, 파일, 변경점과 보류한 hardening을 기록한다.
9. Alpine runtime, proot, 전체 chat UI, 다른 provider 코드는 가져오지 않는다.

포팅 대상은 활성 계획의 `포팅할 참조 소스` 절에 고정되어 있다. 핵심 클래스는 다음과 같다.


## 10. 보안 및 구현 경계

- access token, refresh token, authorization code, PKCE verifier와 state를 logcat, UI, Intent, summary JSON에 넣지 않는다.
- client secret이나 API key 입력 기능을 만들지 않는다.
- endpoint, client ID, scope, callback을 사용자가 편집하는 일반 provider UI를 만들지 않는다.
- Codex 요청에 tools, command 실행, 파일 변경, 브라우저 검색 기능을 넣지 않는다.
- token은 고정 token endpoint에만, access token은 고정 Responses endpoint에만 전달한다.
- inference POST는 명시적 idempotency 계약이 없으므로 자동 재시도하지 않는다.
- 401은 refresh 1회까지만 허용하고 다시 실패하면 재로그인으로 전환한다.
- 429, 5xx와 timeout은 현재 unit을 checkpoint한 뒤 명시적 재개 대상으로 남긴다.
- 기존 source의 account ID metadata는 provider header 호환에만 사용하고 앱 인증·권한 판단에 사용하지 않는다.
- 전사 원문 전체를 OAuth 저장소, 일반 로그, crash report 또는 summary checkpoint에 복제하지 않는다.
- endpoint/header/model의 upstream 변경 시 요약 기능만 비활성화하고 STT 기능은 유지한다.
