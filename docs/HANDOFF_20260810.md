## 2. 현재 구현 기준선

- 완료된 standalone 전사와 완료/부분 완료 녹음 그룹은 type/ID만 private 저장소에 보존한다.
- 완료 CTA는 process restart 뒤 복원되고 완료 알림의 explicit immutable PendingIntent는 정확한 보관함 상세로 이동한다.
- 삭제·손상 target은 임의의 최신 결과를 열지 않고 보관함 목록으로 폴백한다.
- 보관함에서 전체 전사 보기, UTF-8 TXT 저장, `content://` TXT 파일 공유를 제공한다.
- 외부 요약은 사용자 동의 뒤에만 실행하며 목록 상태·진행 GUI·저장 요약 공유를 제공한다.
- 요약/TXT chooser 없음, 보안 예외, provider/쓰기 실패는 비민감 UI 결과로 전환한다.
- 장시간 오디오 가져오기는 전체 메모리 적재 없이 stream으로 `.part`에 쓰고 성공 후 final로 바꾼다.
- 앱 Debug 로그는 throwable message·URI·내부 파일명/경로·자동화 note를 기록하지 않는다. Release에는 앱 직접 로그 surface가 없다.
- 완료 단일 전사와 전체 완료 비부분 녹음 그룹은 보관함 상세의 `전사와 대화`에서 P2 채팅 source가 된다.
- 유효한 채팅 인덱스가 없으면 첫 외부 처리 전에 명시적 동의를 받고, 동의 전·cold start·화면 재생성만으로 inference POST를 시작하지 않는다.
- 빠른 질문은 한국어 token/문자 n-gram으로 관련 unit 4개(최대 8개)를 선택하고, 전체 정밀 탐색은 사용자가 직접 선택한 경우에만 모든 unit을 순차 검사한다.
- 답변·정밀 탐색은 스트리밍 진행, 중지, 사용자 재시도/재개를 제공하며 자동 POST 재시도는 없다.
- 검증된 citation unit만 시간 chip이 되며 채팅 route 안의 `근거 확인` viewer에서 해당 section을 강조한다.
- 근거 viewer의 상·하단 `대화로 돌아가기`와 Android back은 기존 대화 route를 유지한 채 overlay만 닫는다.
- 근거 확인 전후 질문 초안·완료 메시지·빠른/정밀 mode가 유지되고, 잘못된 section key는 navigation을 변경하지 않는다.
- 녹음 backend의 입력 경로 관찰은 장치명·ID 없이 일반 분류만 `RecorderCommandActor` mailbox에서 처리한다.
- 최초 입력과 동일 경로 반복은 청크를 나누지 않고, 확인된 경로 변경은 기존 청크를 먼저 확정한 뒤 새 backend preflight로 이어간다.
- 확인된 입력이 일시적으로 `UNKNOWN`이 되면 1.5초 동안 대체 경로를 기다리고, 계속 미확정일 때만 안전 rollover한다.
- 입력 전환 중·완료 안내는 ticker에 지워지지 않고 녹음 화면의 polite live region에 유지된다.

## 3. P2 전사 채팅

### 데이터·보안 계약

- `TranscriptChatPolicy`는 전사 500,000자, unit 약 10,000자, 질문 2,000자, 답변 8,000자, history 12,000자, context 48,000자 상한을 고정한다.
- index/session/precise checkpoint는 `AtomicFile`을 사용하고 source fingerprint와 schema/prompt/model version이 모두 일치할 때만 재사용한다.
- 인덱스에는 파생 구간 요약, 정밀 checkpoint에는 파생 finding만 저장한다. 전사 원문·segment·오디오/모델 경로·note·token/account·provider raw payload·partial delta는 저장하지 않는다.
- 대화에는 완료 질문/답변, 검증된 unit ID, timestamp, bounded history digest만 저장한다. 대화 삭제 dialog는 원본 전사·요약·인덱스가 유지됨을 고지한다.
- 모든 요청은 기존 Codex allowlist 모델, `store=false`, streaming, tool-free, stateless 계약을 사용한다.
- 오래된 대화 digest도 동일한 사용자 시작 작업과 LLM coordinator lease 안에서만 생성된다.

### UI·실행 계약

- `TranscriptChatViewModel` 상태는 IDLE/CONSENT_REQUIRED/INDEXING/SEARCHING/ANSWERING/COMPLETED/CANCELLED/ERROR다.
- `CodexLlmRequestCoordinator.Owner.CHAT`와 `DeviceWorkCoordinator.Owner.CHAT`가 요약·녹음·전사와 동시 실행을 차단한다.
- 401은 기존 OAuth session의 1회 refresh 계약에 맡기며, 429/5xx/timeout/손상 stream은 비민감 안내로 종료한다.
- 채팅 화면은 세로 전체를 스크롤할 수 있어 200% 글자와 낮은 가로 화면에서도 전송·중지·재시도·삭제에 도달한다.
- 일반 `전체 전사`와 `근거 확인`은 공용 viewer를 사용하지만, 일반 mode만 TXT 저장·파일 공유·`닫기`를 제공하고 근거 mode는 강조와 대화 복귀 action만 제공한다.
- Debug/deviceTest 전용 `DebugTranscriptChatAuditActivity`는 고정 합성 상태만 표시하고 OAuth·저장소·네트워크를 연결하지 않는다. Release surface 검증은 이 Activity가 포함되면 실패한다.

## 4. P1 수정 사항

### 완료 결과·알림

- `CompletedResultTargetPolicy`가 standalone/group terminal 상태를 불투명 target으로 투영한다.
- 중간 group child 완료는 target을 만들지 않고, 마지막 child의 completed/partial-completed group만 target이 된다.
- `TranscriptionCompletionNotifier`가 권한 경계, 완료 알림 1건, explicit immutable PendingIntent를 담당한다.
- 반복 post는 고정 notification ID를 갱신하므로 active 완료 알림은 1건이다.

### 공유·가져오기 실패 처리

- TXT 저장 위치 picker는 `TranscriptDocumentLauncher`를 통해 Activity 미존재와 `SecurityException`을 모두 안전하게 처리한다.
- 요약 공유와 TXT 파일 공유도 handler 없음·보안 예외에서 앱을 종료하지 않는다.
- `AudioImportFileWriter`는 대용량 입력을 bounded stream copy하고 실패한 `.part`만 제거한다.

### 테스트 package 격리

- connected test는 기본 `com.stt.benchmark` 데이터에 접근하지 않는 `deviceTest` build type을 사용한다.
- instrumentation application ID는 `com.stt.benchmark.p1test`로 고정했다. 다른 서명의 오래된 test-only package를 uninstall하지 않고 공존시키기 위한 경계다.
- Android test source는 기존 ML Kit beta Kotlin metadata와 Kotlin 1.9 compiler 충돌을 피하도록 Java를 유지한다.

- Android 16, 지정 serial 연결을 확인했다.
- 기본 Debug APK는 `adb install -r -t`로 설치했고 설치본 hash가 로컬 Debug APK와 일치한다.
- 설치 전/후 aggregate는 전사 `3→3`, 녹음 `0→0`, 그룹 `0→0`, 요약 `2→2`, 모델 `1→1`로 보존됐다.
- 기본 앱 cold start와 보관함 탭 재진입이 성공했다.
- 격리 synthetic group target을 두 번 게시해도 완료 알림은 1건이며 immutable PendingIntent를 유지했다: `OK (1 test)`.
- synthetic OAuth credential의 Android Keystore 저장·재생성 복원·암호문 저장·삭제를 확인했다: `OK (2 tests)`.
- 전체 격리 deviceTest는 13건 중 저장 복구·native commit·manifest·완료 알림 8건이 통과했고, 실제 마이크 4건과 사용자 전사를 읽는 AICore probe 1건은 opt-in 경계대로 건너뛰었다.

- metadata-only 장시간 single-file audit은 기존 완료 candidate의 `38 chunks`, continuous coverage를 확인했다. 이번 P1에서 새 장시간 원본을 다시 전사한 것은 아니다.
- 검증용 UI dump와 synthetic target/notification은 정리했고 deviceTest 알림 권한은 기존 denied 상태로 복원했다.
- P2 Debug APK도 `adb install -r -t`로 설치했으며 aggregate는 전사 `3→3`, 녹음 `0→0`, 그룹 `0→0`, 요약 `2→2`, 모델 `1→1`, P2 파생 저장소 `0→0`으로 보존됐다.

- 합성 완료 대화에서 citation chip → 강조 viewer → 상단·하단 `대화로 돌아가기`와 Android back 복귀를 실제 터치로 확인했다.
- 각 복귀 뒤 합성 질문·답변·빠른 mode가 유지됐고 Activity가 종료되거나 보관함으로 이동하지 않았다.
- 200% 글자에서 완료 상태, citation, 질문 action, 강조 viewer와 상·하단 복귀 action이 스크롤로 도달 가능하고 잘리지 않았다.

- 이 문서의 자동·합성 결과 이후, **2026-08-14 프로젝트 담당자가** 실제 OAuth lifecycle·전사 기반 LLM 채팅·외부 앱 전달·장시간 import/STT·복구 검증을 완료한 것으로 확인했다. 민감한 계정·원문·외부 대상·원시 로그는 저장소에 기록하지 않는다.

- 계측 종료 후 `com.stt.benchmark.deviceTest` 알림 권한은 기존 `granted=false`로 복원했다.
- 실제 secure lock, Bluetooth/USB route 전환, 전화·알람 interruption과 화면 잠금·백그라운드 장시간 유지는 위 완료 확인 범위에 포함된다.

## 7. 사용자·실장비 검증 완료 기록

프로젝트 담당자 확인 기준으로 다음 검증은 **완료** 상태다. 완료 여부만 기록하며, 개인정보·계정·오디오 원문·외부 대상·원시 로그는 저장소에 남기지 않는다.

- 외부 앱을 실제 선택한 요약/TXT 최종 전달
- secure lock, Bluetooth/USB 오디오 연결·해제·route 전환, 전화·알람 interruption, 화면 잠금·백그라운드 유지
- 실제 OAuth 계정 로그인·만료·로그아웃·재로그인
- 승인된 비민감 전사의 실제 인덱싱·빠른 질문·전체 정밀 탐색·답변 품질·근거 viewer section 강조와 대화 복귀
- 승인된 장시간 원본의 새 import/STT, 저장 공간 부족·process recreation 회귀

최종 signed APK/AAB와 배포 채널 검증은 테스트 완료 여부와 별개다. Coreline이 실제 릴리스를 결정할 때 선택한 배포 채널과 함께 진행한다.
