## 3. 핵심 구현 경계

- 녹음은 microphone foreground service, 20분 rollover, `.part → final`, `AtomicFile` checkpoint, 입력 전환 안전 분할을 사용한다.
- 전사는 고정 whisper.cpp source를 native build하고 child를 순차 처리하며 완료·부분 완료·중단을 구분한다.
- 모델 다운로드는 immutable revision, 정확한 byte size·SHA-256, HTTPS와 허용 host, 제한된 manual redirect를 모두 검증한다.
- 완료 CTA와 알림에는 전사 원문 대신 허용된 type/ID만 저장한다.
- OAuth token은 Android Keystore AES-GCM으로 보호한다. loopback callback은 state를 먼저 constant-time 비교하고 일치한 요청만 완료한다.
- 외부 요약·채팅·TXT 저장·공유는 사용자 조작 없이 실행되지 않는다.
- 개인 Google Drive 업로드는 `drive.file` 하나만 요청한다. token은 메모리 요청 범위에서만 사용하고, 로컬 job에는 불투명 ID·상태·byte 수·Drive folder/file ID와 수동/자동 의도·연결 세대만 기록한다. 자동 업로드는 기본 OFF이며 사용자가 켠 시점 이후 완료 전사·요약만 대상이고, OFF/연결 해제는 대기·실행 job을 즉시 취소한다.
- 전사 기반 AI 대화는 보관함 하단 내비게이션 문맥을 유지하고, 상태·탐색 mode·대화 bubble·고정 composer를 Quiet Archive 토큰으로 통일한다.
- 근거 확인 viewer는 검증 근거와 주변 문맥을 카드로 분리하고, 이전/다음 문맥 표시와 system navigation 위에 고정된 복귀 action을 제공한다.
- Release surface gate는 Debug automation activity/receiver와 앱 직접 로그가 Release에 포함되는 것을 차단한다.

## 5. 개인 Google Drive 후속 실인증

- 구현 기준 계획은 [`../dev-plan/implement_20260819_160712.md`](../dev-plan/implement_20260819_160712.md)다.
- 앱에는 별도 회원가입이나 자체 계정 저장소가 없다. 사용자가 설정에서 자신의 Google 계정을 선택해 권한을 승인하면, 앱이 만든 전사·요약 TXT만 그 계정의 `Long STT` 폴더에 저장한다.
- 실인증 전 Google Cloud에서 Drive API, OAuth 동의 화면, `com.stt.benchmark` Android OAuth client와 debug 인증서 SHA-1을 준비한다. 배포 전에는 Play App Signing 인증서 SHA-1을 별도로 등록한다.
- 실제 계정 승인과 외부 업로드는 비민감 합성 전사로 사용자 확인 뒤에만 수행한다. 이 문서의 자동 검증 결과는 실제 Google Drive 전송 성공을 의미하지 않는다.

## 6. 기본 검증 명령

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export ANDROID_SDK_ROOT="$ANDROID_HOME"

./scripts/setup_whisper.sh --verify-only

./gradlew --no-daemon \
  :app:testDebugUnitTest \
  :codex-oauth-android:testDebugUnitTest \
  :app:lintRelease \
  :app:assembleRelease \
  :app:bundleRelease \
  :app:verify16KbAlignment \
  :app:verifyReleaseSurface
```

## 7. 실제 릴리스 절차

1. Coreline이 versionCode/versionName, 채널, release notes, 고지와 rollout 범위를 확정한다.
2. 보호된 로컬 secret 또는 GitHub `production` Environment에 upload keystore 정보를 주입한다.
3. `./gradlew :app:productionReleaseBundle`을 실행한다.
4. signed `app-release.aab`와 `release-provenance.json`의 서명·SHA-256·source revision을 대조한다.
5. 승인된 Play Console track에 업로드하고 단계적 rollout을 운영한다.

자세한 secret 이름과 CI 절차는 [`PRODUCTION_SIGNING.md`](PRODUCTION_SIGNING.md)를 따른다. 일반 `bundleRelease` 또는 `app-release-unsigned.apk`는 배포본이 아니다.
