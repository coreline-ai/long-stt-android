## 프롬프트 기록과 재현용 프롬프트

이번 실행에서는 OpenAI API에 아래 문자열을 전송한 것이 아니다. 현재 Codex 세션의 작업 지시와 문맥을 사용해 같은 요약 규칙을 적용했다. 아래 프롬프트는 추후 백엔드에서 이번 방법을 재현하기 위한 운영용 템플릿이다.

### 0. 시스템 프롬프트

```text
당신은 한국어 장시간 음성 전사 전문 요약기다.
오직 제공된 전사와 이전 단계의 구조화 결과만 근거로 사용한다.
원문에 없는 사실, 인물, 숫자, 의도, 결론을 추가하지 않는다.
모든 핵심 내용은 sourceRange 또는 timeMs로 원문 위치를 추적할 수 있어야 한다.
화자의 의견·경험담·추정과 검증된 사실을 구분한다.
STT 오류 가능성이 있는 고유명사·금액·제품명은 임의로 교정하지 말고
uncertain=true와 이유를 기록한다.
인사말과 의미 없는 반복은 줄일 수 있지만 새로운 주제, 반론, 결정,
실행 항목은 생략하지 않는다. 결과는 한국어로 작성한다.
지정된 JSON 스키마만 출력한다.
```

### 1. 약 30분 단위 구조화 요약 프롬프트

```text
다음은 장시간 전사 중 한 구간이다.

sourceSessionId: {{SOURCE_SESSION_ID}}
sourceHash: {{SOURCE_SHA256}}
unitIndex: {{UNIT_INDEX}} / {{UNIT_COUNT}}
sourceRange: {{START_MS}}~{{END_MS}}
transcript:
{{TRANSCRIPT_TEXT}}

이 구간을 빠짐없이 분석해 아래 JSON 구조로 반환하라.
{
  "schemaVersion": "summary-unit-v1",
  "sourceSessionId": "string",
  "sourceRange": {"startMs": 0, "endMs": 0},
  "title": "string",
  "keyPoints": [
    {"point": "string", "evidence": "원문을 길게 복사하지 않은 근거 요약",
     "timeMs": 0, "confidence": 0.0, "claimType": "fact|opinion|anecdote|estimate"}
  ],
  "examples": [{"summary": "string", "timeMs": 0}],
  "numbers": [{"value": "string", "context": "string", "timeMs": 0,
               "uncertain": false}],
  "decisions": [{"decision": "string", "timeMs": 0}],
  "actionItems": [{"action": "string", "owner": "unknown|string", "timeMs": 0}],
  "risks": [{"risk": "string", "timeMs": 0}],
  "uncertainties": [{"text": "string", "reason": "string", "timeMs": 0}]
}

규칙:
- 제공된 sourceRange 밖의 내용을 추정하지 않는다.
- 불명확한 이름과 숫자를 상식으로 보정하지 않는다.
- 새로운 내용, 관점 전환, 반론, 결정 및 실행 항목을 누락하지 않는다.
- 같은 의미의 반복만 합친다.
```

### 2. 13개 구간 병합 프롬프트

```text
아래에는 시간순으로 정렬된 전체 구간 요약 {{UNIT_COUNT}}개가 있다.
{{UNIT_SUMMARIES_JSON}}

모든 sourceRange가 빠짐없이 반영되도록 병합하라.
반복되는 주장은 하나의 theme으로 묶되 최초·후속 시간 범위를 보존한다.
화자 또는 구간 사이의 차이, 반론, 태도 변화는 억지로 단일 결론으로 만들지 않는다.
숫자와 고유명사의 uncertainty를 유지한다.

다음 JSON만 반환하라.
{
  "schemaVersion": "summary-merge-v1",
  "coveredRanges": [{"startMs": 0, "endMs": 0}],
  "themes": [{"theme": "string", "summary": "string",
              "sourceRanges": [{"startMs": 0, "endMs": 0}]}],
  "timeline": [{"startMs": 0, "endMs": 0, "summary": "string"}],
  "decisions": [],
  "actionItems": [],
  "risks": [],
  "unresolvedUncertainties": []
}
```

### 3. 사용자용 최종 요약 프롬프트

```text
다음 병합 결과만 사용해 한국어 최종 요약을 작성하라.
{{MERGED_SUMMARY_JSON}}

출력 항목:
1. 전체 핵심 요약
2. 핵심 주제와 근거 시간 범위
3. 약 30분 단위 시간대별 요약
4. 결정 및 실행 가능한 원칙
5. 위험과 확인이 필요한 불확실성

새 사실을 추가하지 말고 중대한 반론이나 예외를 삭제하지 않는다.
각 핵심 주제는 최소 한 개의 sourceRange를 포함한다.
사용자가 원문을 다시 확인해야 할 이름·숫자는 확정적으로 표현하지 않는다.
```

운영 환경에서는 프롬프트 버전, JSON 스키마 버전, 모델 ID와 모델 설정을 모두 결과에 저장한다. 모델은 서버 설정으로 교체 가능하게 하고, 동일한 검증 세트로 정확도·누락률·시간·비용을 비교한 뒤 변경한다.

## 전체 핵심 요약

이 방송은 AI 자동화·교육·콘텐츠·시스템 구축을 업으로 삼는 네 명이 약 6시간 동안 나눈 대화다. 반복되는 핵심 결론은 AI 도구 자체보다 `도메인 경험`, `축적된 개인·업무 데이터`, `문제 정의`, `마케팅과 판매`, `실행력`이 성과를 좌우한다는 것이다. AI는 이미 가진 능력을 크게 증폭하는 레버리지이므로 기반 역량이 없는 상태에서 최신 도구만 익혀서는 지속적인 사업 성과가 나오기 어렵다.

실무에서는 ChatGPT·Claude·Gemini·Codex 등을 한 모델에 고정하지 않고 병렬로 사용한다. 기획, 구현, 검색, 검토 역할을 나누고 긴 작업은 새 세션으로 넘기며, 이전 세션의 결정·맥락·다음 행동을 자동 기록한다. 충분한 데이터와 권한이 있으면 브라우저 조작, 시스템 설정, 영상 편집, 계약서·제안서 생성, 세금계산서 발행, 고객 응대와 마케팅까지 연결할 수 있다. 다만 고객정보·회사 기밀·인증정보처럼 본인이 책임질 수 없는 데이터는 외부 모델에 보내지 않는 경계가 필요하다고 강조한다.

사업 관점에서는 사람이 매번 투입되는 맞춤 대행업의 가치가 빠르게 낮아지고 있다고 본다. 도메인 보유자가 AI로 직접 도구를 만드는 속도가 외부 개발자의 요구사항 학습 속도보다 빨라졌기 때문이다. 따라서 고난도 엔터프라이즈 통합을 제외하면, 고객이 직접 만들 수 있게 돕는 템플릿·교육·플랫폼·디지털 상품처럼 고객 수가 늘어도 사람의 업무량이 거의 늘지 않는 구조가 유리하다고 제안한다.

콘텐츠와 마케팅에서는 완성도 100점짜리 하나보다 짧은 시간에 90점짜리를 반복 생산하는 전략, 그리고 제품 기능보다 창업자·제작자의 서사와 신뢰를 축적하는 전략이 강조된다. 유튜브와 SNS는 단순 조회수 채널이 아니라 얼굴·생각·실행 기록을 축적하는 포트폴리오다. 라이브 영상에서 전사, 무음 제거, 쇼츠 추출, 썸네일, 업로드 예약까지 자동화하는 사례와, 지원자 60여 명에게 개인화된 피드백을 제공한 사례는 AI가 효율뿐 아니라 정성을 확장하는 데도 쓰일 수 있음을 보여준다.

장기적으로는 사람이 지시할 때만 움직이는 자동화를 넘어, 매출·미수금·개발 변경·회의 기록을 스스로 분석하고 다음 행동을 먼저 제안하거나 실행하는 AI 네이티브 회사가 목표로 제시된다. 사람은 방향과 가치 기준을 정하고, AI가 반복 실행과 자가 개선을 담당한다. 동시에 사람이 최종 승인 병목이 되거나 잘못된 자동 실행이 확대될 위험이 있으므로 명확한 권한 범위, 감사 기록, 되돌리기, 금액·개인정보·대외 발송 승인선이 필요하다.

마지막으로 자동화로 확보한 시간을 다시 일로 채우는 대신 가족·건강·오프라인 관계·휴식에 쓰는 것이 중요하다고 정리한다. AI 시대에 인간에게 남는 역할은 단순 컴퓨터 작업보다 사람을 만나 신뢰를 만들고, 무엇을 할지 선택하며, 결과에 책임지는 일에 가깝다는 결론이다.

| `06:00~06:13` | 데일리·위클리 경영 리포트와 이상 징후 선제 처리, 사람이 없어도 운영되는 회사, 건강 관리와 각자의 생존 전략을 고민하자는 마무리. |

## 실행 가능한 원칙

1. 도구를 배우기 전에 해결할 문제와 보유 데이터를 정리한다.
2. 하나의 모델에 의존하지 말고 생성·검토·검색·구현 역할을 분리한다.
3. 긴 작업은 세션 종료 시 결정, 근거, 미완료 항목, 다음 프롬프트를 저장한다.
4. 회의·상담·강의는 녹음과 전사를 기본 데이터로 만들되 동의와 보안 등급을 적용한다.
5. 고객·회사 데이터, 인증정보, 결제정보는 외부 전송 전에 제거하거나 전송 금지한다.
6. 초안 생성이 아니라 발행·전달·회계·후속 조치까지 연결하되 위험한 동작은 승인선을 둔다.
7. 고객 수가 늘어도 사람 업무량이 거의 늘지 않는 상품과 운영 구조를 우선한다.
8. 작은 금액이라도 실제 판매하고 반응을 측정한 뒤 가격과 품질을 조정한다.
9. AI 결과의 전문 분야 조언과 숫자는 사람이 검증하고, 모르는 도메인을 아는 척하지 못하게 한다.
10. 자동화로 확보한 시간의 일부를 가족·건강·오프라인 관계에 명시적으로 배정한다.

## 앱에 적용할 외부 LLM 구조

```text
Android 앱
  └─ 완료 전사 + 사용자 전송 동의
       └─ 자체 Summary Backend (API 키 보관, 인증, 속도 제한)
            ├─ 1차: 10분 청크 3개씩 13개 구간 구조화 요약
            ├─ 2차: 인접 구간 요약 병합
            └─ 3차: 전체 핵심·시간대별 요약 생성
                 └─ Android 앱의 SummarySessionStore에 결과 저장
```

- Android APK에는 외부 LLM API 키를 포함하지 않는다.
- source session ID, source hash, 구간 start/end ms, prompt/schema version, model ID를 모든 결과에 저장한다.
- 1차 결과는 `keyPoints`, `examples`, `numbers`, `decisions`, `actions`, `uncertainties`, `sourceRange`의 고정 JSON schema로 받는다.
- 13개 1차 단위를 독립 호출하고 각 성공 결과를 checkpoint해서 재시도 시 완료 단위를 재사용한다.
- 최종 요약은 원문 전체를 다시 보내기보다 1차 결과와 필요한 근거 구간만 사용한다.
- 요청은 기본적으로 stateless와 `store: false`를 사용하고, 조직의 데이터 보존 정책과 Zero Data Retention 적용 여부를 별도로 확인한다.
- 사용자가 외부 전송 대상과 보존 정책을 확인하고 명시적으로 동의한 세션만 보낸다.
- 취소·삭제 시 앱 결과, 백엔드 작업, 임시 원문을 각각 삭제하고 감사 로그에는 원문이 아닌 hash와 상태만 남긴다.

## 현재 실행 판정

- 현재 Codex 세션을 통한 전체 전사 계층 요약은 완료했다.
- 별도 OpenAI API 호출은 자격 증명이 없어 실행하지 않았다.
- 앱 서버 기능 구현 전에는 provider 계정, 자체 백엔드 배포 위치, 사용자 인증 방식, 보존 정책을 확정해야 한다.
